# ADR-0003：數量一律以基準單位入庫，「張」只存在顯示層

- 狀態：Accepted
- 日期：2026-07-30

## 背景

台股專家在週記填「1000」＋單位「張」，實際意思是 1000 股（= 1 張）。
`trade_records.quantity` 有時存張、有時存股，導致減碼校驗「2 張 vs 1000 股」誤放行、
持倉張數放大 1000 倍、報酬率全錯。

## 決策

- 資料庫 `quantity` 一律存 **Base Unit（基準單位）**：台股＝股、加密＝顆、美股選擇權＝口、Combo＝組。
- `quantity_unit` 只記錄「使用者當初輸入時的顯示單位」，不參與任何計算。
- 顯示層由 `src/lib/positionQuantity.ts` 的 `formatBaseQuantity()` 決定文案（1000 股 → 「1 張」）。
- 同一標的未平倉期間**單位鎖定**：後續訊號的單位必須與既有部位一致，UI 直接 disable 選單。
- 驗證前移到輸入當下（`collectTradeIssues`），不等送出才由 DB 打槍。

## 替代方案

- **以「張」為台股基準單位**：零股、美股、加密、選擇權全都無法統一，換算點反而更多。
- **每個資產類別各自一套換算**：等於把換算責任丟回呼叫端，就是原本錯誤的來源。

## 後果

- 歷史資料需一次性 migration（已完成），任何新寫入路徑都必須先 `normalizeQuantityToBaseUnits()`。
- Edge Function 與前台共用同一組單位規則，任何一邊繞過都會讓持倉統計失真。
