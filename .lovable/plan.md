# 訂閱者表格資訊加厚 + 到期會員收不到通知（已查出根因）

## 先回答：廖基富為什麼不是足月到期

查正式資料（唯讀）：

- 起始日欄位 2026/07/27、到期日 2026/09/06、訂閱建立於 2026/08/06 22:55
- 付款紀錄只有一筆：NT$799，付款時間 2026/08/06 22:55

到期日 = 付款時間 + 一個月（8/06 → 9/06），這段是足月的。看起來不足月，是因為**起始日欄位被填成 7/27，比實際付款日早了 11 天**。表格只秀「起始日／到期日」，就變成 7/27–9/06 這種對不起來的區間。

## 為什麼到期會員說沒收到通知（根因，非猜測）

會員端的到期提醒只有兩條路：

1. Email（每日 09:10 台北）— **全部失敗**。寄信服務金鑰無效，紀錄裡只有 4 筆 `renewal_email_failed`（最近 9/19），成功紀錄 0 筆，錯誤訊息一律是「API key is invalid（401）」。
2. LINE — 只有綁過 LINE 的會員收得到，其餘直接略過。

而且**站內通知完全沒有做會員端的到期提醒**：通知表裡跟到期有關的只有發給老師的 `subscriber_expiry_reminder`，會員本人一筆都沒有。廖基富站內通知數 = 0。

結論：不是漏發某一位，是所有會員的到期提醒都沒送出去。

## 要做的三件事

### 1. 訂閱者表格資訊加厚
每列補上：註冊時間、首次付款時間、最近一次付款時間與金額、起始日、到期日、期數。
起始日與首筆付款日差距超過 3 天時，在該列標一個文字提示（例如「起始日與付款日差 11 天」），避免再出現廖基富這種看起來不足月的情況。
可展開的每期歷史同步顯示該期的付款時間與金額。

### 2. 會員到期提醒補站內通知通道
新增會員端站內通知（T-7 / T-3 / T-1 / 到期當日 / 過期 24 小時內），與 Email、LINE 各自獨立成敗，任一條通失敗不影響其他條。站內通知不依賴外部服務，這是最能保證「會員一定看得到」的一條。
同時在會員帳號頁的續訂橫幅維持既有顯示邏輯，不改規則。

### 3. 管理頁看得到每位會員的提醒狀態
訂閱者列表加「會員提醒」欄：站內／Email／LINE 三個狀態（已送出／失敗／略過／待送），滑過看時間與失敗原因，老師與管理員可以自己判斷要不要私下通知。
