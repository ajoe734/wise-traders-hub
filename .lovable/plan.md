# 全市場個股分類重建（細分產業＋題材）

## 現況（已查證）

- 目前看板的產業只有三層：5 檔手工校訂（`stockIndustry.json`）→ 交易所官方大類（`twsePrimaryIndustry.json`，1,982 檔）→ 次分類（2,530 檔）→ 未分類。
- 也就是說，除了 5 檔之外，全市場都只有「半導體業」「電子零組件業」這種粗分類。創意（3443）在官方資料就是「半導體業」，看板自然分不出它是 ASIC 設計服務。
- 估值三把尺的同業母體 `tw_industry_peers` 共 2,816 檔、只有 53 個大類，其中「電子工業」232 檔、「半導體業」228 檔，拿來比本益比參考價值低。
- 個股覆寫表 `holding_meta_overrides` 目前 0 筆，手動修正管道已存在但沒人用過。

## 目標

建立一套涵蓋全市場約 1,965 檔的**細分產業**分類，外加**題材標籤**，直接生效，錯的用既有的個股覆寫功能修正。

## 一、分類體系（先定字典，再分類）

建立唯一字典檔，所有分類只能從字典挑，不得自由發明：

- **細分產業**：約 70 類，掛在 12 個大類下。例如半導體大類拆成 IC 設計、ASIC 設計服務、矽智財 IP、晶圓代工、記憶體、封裝測試、半導體設備、半導體材料；電子零組件拆成散熱模組、被動元件、連接器、電源供應、機殼、PCB／CCL、光通訊模組、面板與零組件等；非電子涵蓋金融、營建、航運、生技、食品、觀光、鋼鐵、塑化、紡織、汽車零組件、綠能等。
- **題材標籤**：約 40 個，跨產業，例如 AI 伺服器、CoWoS／先進封裝、低軌衛星、機器人、車用電子、重電、資安、無人機、生技新藥、高股息。
- **非個股**（ETF、ETN、存託憑證、創新板等）走規則判定，不進分類流程。

創意的預期結果：細分產業「ASIC 設計服務」，題材「AI 伺服器」。

## 二、分類資料表與產生流程

- 新增資料表存放全市場分類：個股代號、市場別、官方大類、細分產業（可多個、含營收比重）、題材、信心度、資料來源、更新時間。公開可讀、只有後端能寫。
- 新增一支後端排程／手動觸發的分類作業：取全市場個股清單與公司基本資料（名稱、官方產業、上市櫃別、營收資料），交由 AI 依字典輸出細分產業（1–3 個並附比重）、題材與信心度，一次處理一批，全市場分批跑完並寫入。
- 分類結果直接生效；低信心的仍會寫入，但在後台列表可篩出來優先檢查。
- 之後新上市個股由每週排程自動補分類。

## 三、看板接線

- 取值優先序改為：個股手動覆寫 → 人工校訂檔 → 新的全市場分類表 → 官方大類 → 未分類。
- 分類表在前台載入一次並快取，之後修正不必重新發布就會生效。
- 族群彙總、族群篩選、集中度警告全部沿用現有邏輯，只是輸入的分類變細。

## 四、估值同業比較

- 同業中位數的母體改用細分產業（依你選的方案）。
- 同業不足 3 家時，維持現有的「同業樣本不足（n=x）」標示，不混算跨市場。

## 五、驗收

- 字典與判定的純函式單元測試；非個股（ETF／ETN／DR）不得被分到產業。
- 全市場覆蓋率讀回：分類筆數、未分類筆數、各細分產業家數分布，並確認沒有單一類別塞進過多家數。
- 人工抽查至少 50 檔（含 3443 創意、3017 奇鋐、6274 台燿、2308 台達電、3491 昇達科、2330 台積電、2882 國泰金、2603 長榮），逐檔列出分類結果對照。
- 真實登入開持倉抽屜，確認族群顯示與同業中位數都換成細分產業。
- 相關測試、型別檢查、模組邊界、建置全綠。

## 技術細節

- 字典：`src/checkup/data/industryTaxonomy.json`（細分產業 → 大類、題材白名單），前後端共用同一份。
- 資料表：`stock_industry_map`（symbol PK、market、official_industry、industries text[]、revenue_mix jsonb、themes text[]、confidence numeric、model、rationale、reviewed bool、updated_at）；RLS public read / service write，含 GRANT。
- 分類作業：Edge Function `stock-industry-classify`，modes `all` / `symbols` / `missing`；來源 FinMind TaiwanStockInfo + `stock_names` + `tw_industry_peers`；AI 走 Lovable AI Gateway，強制 JSON schema 且 enum 限定字典值，超出字典的回傳一律丟棄重判；批次 20 檔／次，含 429/5xx 退避與失敗落地。每週排程補新股。
- 前台：`stockMetaMulti.js` 新增 `autoMap` 參數層（介於人工校訂與 TWSE 之間），新增 `useStockIndustryMap`（一次載入＋localStorage 快取，走既有 `createPrefsStore` 慣例）；保持純函式、不在元件內直接查 DB。
- 估值同業：`valuation_snapshot` RPC 的 peers 母體改讀 `stock_industry_map` 主細分產業，`tw_industry_peers` 保留為官方大類備援欄位。
- 不改 BSR 移除、估值回補資料與排程 110/111。
