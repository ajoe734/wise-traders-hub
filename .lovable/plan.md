# 前端只讀資料庫：停止頁面請求即時抓外部財報資料

## 現況（已查證）
- 抽屜估值接口 `valuation-fundamentals`：先讀 `valuation_filing_versions`，沒有就**當場打 FinMind**（目標公司 3 次＋同業），這是額度被頁面／測試吃掉的主因。
- 走勢小圖 `checkup-sparkline`：資料不足時當場依序打 TWSE → TPEx → FinMind。
- 籌碼 `tw-chips-detail` 已主要讀資料庫，回補走排程佇列。
- 每天 03:00 的線上巡檢（live-smoke）打的是正式接口，所以冷快取時每次都觸發外部抓取。

## 要改成
```text
排程（後端）: 外部來源 ──> 資料庫（財報版本、股價、籌碼）
頁面／測試  : 只讀資料庫 ──> 沒資料就顯示「資料準備中」，並排入回補佇列
```

1. `valuation-fundamentals` 改純讀：只讀財報版本表＋官方股數名錄＋已存股價；缺資料回 `pending` 並寫入既有財報佇列（`selectFilingQueue` 處理），**不在請求中呼叫 FinMind／官方網站**。
2. 5 年股價改由排程寫入資料庫（沿用既有每日股價同步表；不足的代碼加入每日排程），估值接口只讀。
3. `checkup-sparkline` 改純讀已存日線；缺資料回空並排回補，不即時打外部。
4. 抽屜與持倉清單：`pending` 時顯示「財報資料準備中」，不畫假站牌（符合既有規則）。
5. 線上巡檢與 E2E：改用固定測試資料或只打不觸發外部的路徑；巡檢加標頭標記為測試，不計入流量。
6. 機制強制：新增靜態測試，掃描上述讀取型接口，出現 FinMind／TWSE／TPEx 網址或 `fetchWithRetry` 即失敗（只允許排程同步函式）。

## 影響與限制
- 剛加入、資料庫還沒有的股票，第一次打開會看到「準備中」，等排程補完（約下一輪）才出現站牌。
- 需部署後端函式（共用後端），不發布正式前台，除非你另外要求。
