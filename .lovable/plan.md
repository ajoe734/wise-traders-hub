# 財報期限停用與公布更新

## 要完成的結果

1. **期限按台北當日判定**：Q1 5/15、Q2 8/14、Q3 11/14、Q4 隔年 3/31，期限當天可推估、隔天零時停用。沒有新季報時 PE／PS 顯示資料不足，PB 不受推估期限影響。週末、休市或舊收盤日期不能延後停用。
2. **提前公布也立即接新季**：不再等法定期限才更新。只在同一季損益、資產負債及必要分母完整核實後前移最新季；不重複推估已公布季，不混用不同季資料。
3. **一起更新**：財報新版本供持倉「已反映程度」、抽屜站牌與 PE／PB／PS 分頁共用；同業 PS 分母更新後補算逐日倍數，PE／PB 仍取交易所公布的實際倍數，不用價格反推財報。
4. **不假裝完成**：資料缺漏、額度用完或供應商尚未更新，留下待處理狀態、原因及紀錄；不能只更新取得時間就取消重試。

## 公布當天的限制與做法

- 現有來源是 FinMind 每日更新的財報資料，未找到可驗證的財報公布即時通知。**目前不能保證「公司公布當天，完整財報必已可取得」**。
- 實作時先驗證上市／上櫃官方整批財報期別索引，涵蓋一般業及金融等特殊格式；成功確認新期別才針對有變動股票抓完整資料，避免每小時掃全市場財報耗盡額度。官方索引失敗不得視為「沒有新財報」。
- 沿用已存在的每小時更新入口，不另建重複排程、不改認證；目前每天執行 **24 次**。資料提供後目標於下一輪開始處理；通常檢查等待不超過一小時，但供應商延遲、處理隊列與配額可能使完成時間更晚，需呈現實際狀態而非保證當天完成。
- 每小時檢查有 recurring Cloud 與資料查詢成本；以整批索引偵測變動、只更新變動檔降低成本。不增加更高頻率。
- 若官方索引無法支援完整範圍，明列缺口；**不偷偷改成整市場高頻輪詢，也不宣稱公布日自動更新已驗收**。

## 技術實作

- 共用純函式處理台北日期、期限、財報完整期別、新版本判定；期限不是用股價的 `asOf`。回傳並分開保留行情日、財報期、資料取得時間。
- 修正 `valuation-fundamentals` 與前端六小時快取：期限跨日重新判定；新財報版本失效舊結果，開著的頁面與背景後返回頁面也刷新，不必等換股票或報價。
- 在既有 `valuation-ps-sync` 入口接公布期別偵測及有界更新；保留每日收盤 PS 與估值市場檔更新。處理排序公平、未完成可重試、重複執行無副作用。
- 用最小後端財報版本／更新狀態保存可讀回成果；完整資料才提交新版本。所有新表顯式 GRANT＋RLS，僅後端寫，會員仍走既有單檔服務，不讀全表。不存用戶持倉作為第二份帳本。
- 本專案缺 managed HTTP schedule helper；**不新增或手寫 HTTP 排程 SQL**，沿用現存排程與認證。若需改排程而平台不支援，列為阻擋項。
- 同步規則文件、issue、架構規則及待辦；不修改尚未核准的極端倍數／異常 EPS 規則，不發布正式前台。

## 完整驗收範圍

- 四季期限當天／隔天、Q4 跨年、台北零時／UTC、週末／舊行情日、缺月營收、提前公布、部分財報、季報修正、虧損／股數不一致／資料不足。
- 前端與後端快取、已開啟抽屜／清單、切股票競態、同業 PE／PB／PS、處理順序與重複執行、超時／配額／官方索引失敗／寫入失敗。
- 官方上市＋上櫃全部支援格式契約驗證，分類字典全範圍的通用性測試，不以幾檔股票替代。
- 跑相關既有及新增測試、模組界線，真實登入讀回完整流程；未能遇到真實新公布事件的部分以受控整合測試驗證並明示，不冒充真實公布日驗收。
