# 持倉抽屜 Bug 全面檢查與修正計畫

## 目前已確認的狀態
- 建置正常、預覽沒有執行錯誤，抽屜可以打開（白畫面已修好）。
- 單元測試 82 項全數通過，手機版版面靜態檢查通過。
- 上一輪自動化瀏覽器測試留下 6 類失敗，還沒有逐項確認是真的 bug 還是測試已過時。

## 待查失敗清單（全部都要處理，不抽樣）
1. **現價圓點尺寸**：圓點目前是 12px，舊截圖基準是 9px（390／768／1280 三種寬度）。要先確認改成 12px 是設計上刻意的改動，還是不小心造成的回歸。
2. **圓點寬度變成 0**：1180／1280／1600px 量到圓點寬度 0。懷疑是切換動畫還在進行時就量測，或是減少動態效果的設定沒有處理到圓點。
3. **分點測試頁**：獨立測試頁（不是抽屜）找不到分點區塊（16 項中 11 項失敗）。抽屜本來就規定不顯示分點；要查測試頁有沒有正確打開分點，或是這次改法人配色時誤傷了分點畫面。
4. **分點手機測試**：完整資料與空資料兩種情境逾時（12 項）。
5. **捲動與溢出**：1440／1920px 捲到底檢查失敗；iPad 820×1180 極端尺寸失敗。
6. **缺漏的覆蓋**：目標價／PE／PB／PS 四段切換還沒有自動化測試；「資料不足不畫區間」與「個人情境只出現在對應的尺」沒有單元測試。

## 修正步驟
1. 每個失敗的測試檔各跑一次（一次只開一個測試程序），取得失敗紀錄與截圖，判斷是程式錯誤還是測試過時。
2. 依結果修：
   - 圓點：如果 12px 是設計要的，就更新截圖基準並寫進 issue；否則改回原尺寸。量測前先等動畫結束；減少動態效果時讓圓點直接以最終大小顯示，不從 0 放大。
   - 分點：只修測試頁或分點畫面本身，抽屜維持不顯示分點。
   - 寬螢幕溢出：修正價格軸與四段切換按鈕的寬度限制。
3. 補測試：四段切換、資料不足時的提示、個人情境只套用在對應的尺、法人同一身份不論買賣都同色、K 線維持紅漲綠跌。
4. 驗證完整範圍：280–2560px 共 24 種寬度、560／390／380px 截圖、iPad、捲到底、法人桌機與手機、圓點形狀與對齊，再跑全部單元測試與型別檢查。
5. 在 roadmap 與 issue 驗收清單上勾選完成，並列出仍未解決的項目和原因。
