# 週記持股時間軸、會員持股總覽與 FinMind 配額擴容

## 目標

1. 週記頁的「目前持股」繼續顯示老師瀏覽當下的真實持倉，並新增可追溯的交易變化時間軸。
2. 週記發布完成時，同步完成持股狀態與歷史事件，會員不需手動更新。
3. 新增會員專屬持股總覽，支援「全部已訂閱老師」與「單一老師」兩種檢視。
4. 將 FinMind `interactive` 內部每日額度由 240 調整為使用者確認的 1,000，並保留上游真實限額保護。

## 已確認的現況

- 週記上的持股卡片已透過 `useExpertHoldingsBundle` 讀取目前未平倉部位，並監聽持股更新；它是即時狀態，不是發布快照。
- `trade_records` 是會被更新的目前持股表，不保留每次加減碼歷史。
- 已發布的 `expert_signals` 多數可重建交易順序，但既有編輯流程可能刪除後重建紀錄，因此不足以作為不可改寫的完整時間軸。
- 週記排程發布會先標記發布，再同步交易與持股；即時發布另有老師編輯器路徑，兩條都必須一致寫入歷史事件。
- `/app/holdings` 目前只會導回會員首頁，可直接改為新的會員持股總覽入口。
- FinMind `interactive` 目前每日額度 240，今天已達 240；近期另有 5,699 次 `daily_exhausted` 拒絕。系統尚未收到可核對的上游額度標頭。

## 功能設計

### 1. 不可改寫的持股變化帳本

- 新增持股事件表，每筆記錄：老師、股票、來源訊號、買進／加碼／減碼／賣出、變動數量、變動後數量、交易價、幣別、資產類別、事件時間與來源類型。
- 事件只追加，不覆寫或刪除；同一訊號具唯一鍵，確保排程重試、人工重送與即時發布不會重複入帳。
- 在既有持股同步的共同資料庫接縫寫入事件，讓排程發布、即時發布與重試都走同一規則。
- 已發布內容若需訂正，新增「訂正事件」而非改寫舊事件；pending 內容仍可沿用既有安全編輯流程。
- 既有已發布訊號做一次受控回補，標示為 `reconstructed`；逐檔比對回放結果與目前持股，不一致者不偽造結果，列入管理員稽核。
- 新表同一 migration 內建立必要 GRANT、RLS、索引與查詢函式；會員只能讀取自己仍有效訂閱老師的事件，管理員與老師權限沿用既有角色函式，不新增前端繞過。

### 2. 週記頁持股時間軸與自動同步

- 在「目前持股」卡片下方加入「持股變化」時間軸；依股票分組，顯示日期、動作、交易價、數量增減與變動後持股。
- 時間軸只記交易變動，不把每次現價跳動存成事件；卡片現價仍使用目前報價。
- 預設顯示最近事件，可展開完整紀錄；缺成交價、重建資料或訂正事件均有明確標示，不推算假價位。
- 週記發布成功的定義擴充為：狀態發布、持股同步、事件入帳三者完成；任何一步失敗都可安全重試且不重複。
- 發布成功後讓既有持股 bundle 與時間軸查詢失效重抓；已開啟頁面透過現有即時更新自動刷新，不需要會員操作。
- `teaching`／`hold` 不改變數量，因此不新增持股事件；既有通知、LINE 推播、週記內容與 PDF 流程不變。

### 3. 會員專屬持股總覽

- 接管 `/app/holdings`，沿用會員登入與訂閱准入；未訂閱任何老師顯示空狀態，不查詢未授權老師。
- 提供「全部老師」與「單一老師」切換：
  - 全部老師：只載入 `useMemberSubscriptions` 回傳的有效訂閱老師，再逐位使用 `useExpertHoldingsBundle` 與各自的公開投影檢核。
  - 單一老師：只顯示該老師持股，並可從週記頁或老師頁進入。
- 排序／分組支援產業、幣別、持倉比例：
  - 跨老師時先按 TWD／USD 分組，各幣別獨立計算比例，絕不把不同幣別直接相加。
  - 單一老師時，以該老師同幣別持股市值為比例分母。
  - 台股產業沿用既有分類字典與 `stock_industry_map`；沒有可靠分類的美股、加密貨幣等顯示「未分類」，不猜測。
- 任一老師投影狀態未 ready 時，該老師所有價格、數量、損益與比例全部遮蔽；其他已 ready 老師可正常顯示。
- 會員首頁增加「持股總覽」入口，週記與老師頁加入對應連結；維持既有五項底部導覽，不硬塞第六項。

### 4. FinMind interactive 擴容

- 將 `interactive` 的 `daily_budget` 與 `base_daily_budget` 調整為 1,000，並安全重置該 pool 當日計數，使升級立即生效；不重置 keepwarm／backfill。
- 同步校準 token bucket 容量，但保留借用保護、kill-switch、熔斷、inflight 去重與 fail-closed 行為。
- 因目前沒有上游額度觀測資料，先不擅自提高全域每小時保護值；部署後以 FinMind 回應標頭與 429 紀錄驗證真實上限，再決定是否需要調整 `FINMIND_HOURLY_LIMIT`。
- 補強管理頁：同時顯示內部每日額度、上游可用額度、拒絕原因與借用量，避免把「內部分配 1,000」誤認成上游保證可用 1,000。
- 抽屜本身仍讀資料庫快照；interactive 額度用於高優先同步，不改成每次開抽屜直接打 FinMind。

## 技術範圍

- 依新功能 issue 範本建立追蹤項目，補齊驗收標準、頁面／路由、資料來源與阻塞項。
- Schema 變更只透過 migration；既有配額數值更新使用資料操作／受保護管理員 RPC，不混入 schema migration。
- 週記讀取仍走 `journalRepository`；前後端鏡像由產生器同步，維持 parity 測試。
- 目前持股仍只走 `useExpertHoldingsBundle`；歷史時間軸使用獨立唯讀 repository/hook，不直接查 `trade_records` 重算。
- 新增架構決策到 `AGENTS.md`：目前持股、交易事件帳本與週記內容各自的唯一責任。

## 完整驗證

- 資料庫：買進、加碼、減碼、部分賣出、全賣、不同單位、跨市場、重試去重、訂正事件、回補一致性、RLS 未授權拒絕、投影遮蔽。
- 發布：排程、即時發布、pending 編輯、已發布訂正、部分失敗重試、teaching／hold、通知與 LINE 不回歸。
- 週記頁：時間軸排序、價格／數量格式、缺值、重建標記、展開收合、即時刷新，以及現有持股卡片所有狀態。
- 總覽頁：無訂閱、單一／多老師、到期移除、TWD／USD 分組、產業未分類、比例分母、排序 tie/null/0、部分老師檢核中。
- 尺寸：1280、721、560、390、380px 截圖與水平溢出檢查；鍵盤操作與減少動態效果。
- 配額：1,000 設定值、當日重置、token refill、借用門檻、kill-switch、熔斷、inflight 去重、429 降級、ledger 歸因與管理頁顯示。
- 跑完整 Vitest、相關 Edge Function Deno tests、週記／持股／訂閱 E2E、型別、RLS 稽核、raw-fetch 稽核、模組邊界、安全掃描與最新建置紀錄。

## 不動範圍

- 不把週記持股改成發布時快照；卡片始終反映目前持有，時間軸負責說明變化過程。
- 不混加 TWD 與 USD，也不新增匯率換算規則。
- 不讓前端持有 FinMind Token，不繞過上游真實方案限制。
- 本次不自動發布正式站；完成與驗證後再依明確發布指示上線。
